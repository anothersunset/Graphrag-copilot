## 2. 问题发现与修复

### 2.1 常量命名不一致

**现象**：`metrics.py` 中 `_REQUIRED_NODES` 与 `__init__.py` 公共 API 的 `EXPECTED_NODES` 不一致。

**修复**：`_REQUIRED_NODES` → `EXPECTED_NODES`，更新 `__all__` 导出。

### 2.2 导入路径错误

**问题**：
- `auditor.py`: `from ..contracts import AuditEntry` → 应为 `from ..state import AuditEntry`
- `evaluator.py`: 同上
- 函数名 `auditor` / `evaluator` → 应为 `auditor_node` / `evaluator_node`（LangGraph 节点命名约定）

### 2.3 evidence 类型导入路径

**现象**：`reference_runner.py` 中 `from graphrag_graph.evidence import` 失败。

**根因**：evidence 类型定义在 `graphrag_schemas` 包中，不在 `graphrag_graph` 中。

**修复**：改为 `from graphrag_schemas.evidence import`。

### 2.4 英文停用词过滤 Bug

**现象**："What is Self-RAG?" 查询中 `is` 词导致 c01 排名高于 c06。

**根因**：`_tokens()` 函数未过滤英文停用词。

**修复**：添加英文停用词过滤（is, the, a, an, of, in, to, for, ...）。

### 2.5 Distractor 未被过滤

**现象**：adversarial 测试中 distractor 文档未被排除。

**修复**：`adversarial_orchestrator_adapter()` 添加 distractor 过滤逻辑，从 `cited_chunk_ids` 和 `claim evidence_ids` 中剥离 distractor id。

### 2.6 代码格式化

62 文件应用 `ruff format` 全量格式化。

## 4. 经验教训

1. **多包 monorepo 的导入关系需要严格维护**：schemas 包的 evidence 类型不应在 graph 包中重复引用
2. **停用词对短查询影响巨大**：一个 `is` 就能翻转检索排序
3. **格式化工具要统一应用**：62 文件在多人协作前最好一次性格式化
4. **Python 版本约束要与实际环境匹配**：`requires-python = ">=3.12"` 改 `>=3.11` 这类修复很常见
